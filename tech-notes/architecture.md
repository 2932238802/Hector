# 技术架构（M0–M2 原型）

> 目标：把 `doc/` 里的回合流程、经济、巢穴与种子跑成**能点、能结算**的可玩版本，
> 用真实代码验证节奏假设。
>
> 文档规则：`draft` 文档可以做原型验证，但**不能作为验收依据**；
> 本文件描述原型实现，不是最终架构。`doc/` 只读，开发中不修改。

## 1. 范围

- **M6（春季切片 v0）**：6 回合、开局 2 次免费招募、事件 `options`、4 组春季敌人、战斗奖励。
- **M7（2026-11-09 对齐）**：
  - **删除工蚁系统**：无人口、无维持费、无蚁后产工蚁 / 被动恢复；回合开始只做收入汇报。
  - **取消战斗补给**（Q-052）：`units.json` 删除 `supply`，布阵确认后直接开战，出战不扣食物。
  - **开局 L1**：7 格 / 3 肥沃格 / 15 食物 / 100 完整度 / 1 颗基础谷种 / 2 次免费招募；
    扩建 L1 → L2 → L3（20 / 30 食物），肥沃格 3 → 6 → 9。
  - **阶级对应**：一阶 = L1 / 二阶 = L2 / 三阶 = L3；概率表键 1 / 2 / 3；升阶保底 2 / 3。
  - **探索改食物代价**：冒险 1–2 食物 + 雨天 / 春季各 +1；事件探索选项同步改食物。
  - **`schema_version: 1`**：`data/*.json` 顶层必填，加载时校验。

## 2. 分层

```
scripts/
├── core/                 # 纯逻辑，不依赖场景树，可无头测试
│   ├── game_state.gd     # 单一状态源 + 回合/战斗/招募/种子状态
│   ├── event_pool.gd     # 事件组生成（静态函数）
│   └── hex_grid.gd       # 轴向坐标 / 圆环 / 方向扇区
├── ui/                   # 场景节点，只读 game 状态并渲染
│   ├── main.gd           # 程序化搭 UI + 刷新
│   └── nest_view.gd      # 六边形巢穴绘制、肥沃格、悬停
└── autoload/             # 预留；当前没有 autoload
```

- **core 不引用任何 UI 类型**，`GameState` 可直接 `new()` 后跑完 24 回合。
- 数据只从 `res://data/*.json` 读；UI 不写状态，只调 `GameState` 的公开方法。

## 3. 状态机

```
ACTION（三选一 + 播种）
  → GROUP_SELECT（3 组选 1）
  → EVENT（A→B→C→D；可插入 BATTLE / RECRUIT）
  → 下一回合 … 第 6 回合结束 → WON
失败：巢穴完整度归零（任意时刻）→ GAME_OVER
```

- `changed` 信号是唯一刷新入口；UI 监听后整体重绘侧栏。
- 事件结算顺序：应用效果 → 种子计数 / 收获 → 健康检查 → 招募 / 下一事件。
- 战斗事件在战斗结束（胜 / 负）后再推进种子计数，保证「1 个事件 = 1 次生产节拍」。

## 4. 关键实现点

### 4.1 巢穴格与肥沃格

- `_rebuild_cells()` 按当前等级铺 `ring_cells(0..level)`（L1 = 中心 + 6 格），
  被位置阻断的方向（`blocked_dirs`）整列标 `blocked=true`（存在但不可用）。
- 肥沃格：每圈固定 3 个，方向 0 / 2 / 4；若该方向被阻断，**顺延到下一个可用方向**，
  所以 L1 河边固定为 3 个可用肥沃格。中心格不是肥沃格。
- 肥沃格位置在扩建时重算；已种下的种子保留 `q/r`，不因重算丢失。

### 4.2 种子

- `data/seeds.json`：`id / name / kind / period / yield / desc`。
- `kind`：`food`（食物）、`warspoil`（战果占位）、`tool_heal`（恢复完整度）。
- `planted` 是 `{seed_id, q, r, counter}` 列表；`counter` 在**每个事件结算后 +1**，
  达到 `period` 时收获并把计数归零。
- 播种不占三选一行动（用户拍板）；只能种在「肥沃 + 未阻断 + 未占用」的格子。
- 产量预测 `_forecast_food_per_turn()` 只算食物型种子在本回合 4 个事件内的收获次数。

### 4.3 扩建

- 文档 `02-systems/economy.md` 6：扩建走巢穴经验线，经验是唯一升级进度，食物可兑换。
  具体兑换率 / 阈值仍是 open（Q-098 / Q-100），原型占位：
  **1 食物 = 1 经验，L1→L2 需 20，L2→L3 需 30**（对应 doc 的 20–30 / 30–40）。
- 三选一「巢穴扩建」：补齐经验差额 → 升级 → 重置经验 → 重算格子。
- 植物受击经验、战果换经验未实现。

### 4.4 战斗 v2（2026-11-09）

- **7 格**：双方各 `front` 4 / `back` 3；不补位，阵亡后位置留空。`battle` 结构为
  `{"player": {"front": [], "back": []}, "enemies": {...}, "round", "event", "result"}`。
- **布阵阶段**（`Phase.DEPLOY`）：列出军队，默认按 `row` 出战；可切前排 / 后排 / 撤下，
  每排容量受限。撤下单位不影响食物。
- **补给**：2026-11-09 已取消（Q-052）。`deploy_supply()` 恒为 0，布阵确认后直接开战，
  出战不扣食物；旧接口保留只为兼容 UI。
- **伤害**：`max(0.1, snapped(攻击 × rand(0.90, 1.10), 0.1))`；护盾先抵扣，
  剩余才扣 HP；HP ≤ 0 退场。无防御、无减伤。
- **目标**：敌方前排全灭前不能选后排；敌方 AI 打我方前排（前排空则打后排），
  在同排里选当前 HP 最低的单位。
- **行动点**：每个单位基础 1 点，玩家阶段开始时回满；未用完不保留。玩家可自由选择
  哪个单位攻击（当前实现为「下一个有 AP 的单位」，UI 点敌方即攻击）。
- **6 轮裁决**：第 6 轮敌方阶段结束仍未分胜负 → 最终裁决，玩家为防守方获胜，
  掉落减半（当前只结算事件 `effects.food` 的一半）。
- **战后回满**：每场战斗从 `units.json` 重建单位，HP 不跨场；阵亡单位返场。
- **避战**：食物不足连一个单位都派不出时的兜底；谈判 / 回避规则未定（Q-084），
  原型按「不结算」处理。

### 4.6 春季切片 v0（2026-11-09）

- **6 回合**：`TOTAL_TURNS = 6`，第 6 回合结束 → `WON`，日志与终局面板输出本季统计
  （食物净变化、完整度变化、战斗场次 / 胜负、虫珀）。
- **开局**：健康 100、食物 15、**L1**、7 格 / 3 肥沃格、1 颗基础谷种、**无固定军队**；
  `start.free_recruits = 2` 次免费招募（3 选 1，免费、不占行动，可跳过）。
- **工蚁系统已删除**（2026-11-09）：没有人口、没有维持费、没有被动恢复；
  回合开始只做收入汇报；巢穴恢复只能靠三选一「巢穴恢复」。
- **扩建 2 次**：L1 → L2（20 食物）→ L3（30 食物），肥沃格 3 → 6 → 9。
- **探索代价改为食物**：冒险基础 1–2 食物，雨天 +1、春季 +1；收益 2–4 食物、可能带种子。
- **春季修正**：食物型种子收获 +1；敌人 HP / 攻击 ×1.1；探索食物损失 +1。
- **结算**：战斗胜利不再用事件 `effects`，改按 `combat.rewards.<tier>` 掷食物 / 战果 / 虫珀；
  普通 2–4 + 50% 战果，强敌 4–6 + 1 战果 + 50% 虫珀；裁决食物减半。

### 4.7 事件 v2（2026-11-09）

- **6 类**：`enemy_weak` / `enemy_strong` / `explore` / `random` / `recruit` / `relic`；
  当前 `data/events.json` 是春季最小集 12 条（内容量仍待扩到 60–77，Q-003）。
- **6 模板**（`data/event_templates.json`）：巡逻 / 远征 / 强敌 / 危机 / 遗迹 / 招募，
  每组固定 4 格，模板顺序即类别顺序（普 → 探 → 随 …）。
- **生成**：按季节权重抽 3 个不重复模板；本轮最多 1 个危机组、1 个含遗迹模板；
  组内同类最多 2 个；每组至少 1 个敌对（模板保证 + 兜底）。
- **事件选项**：`choose_event_option(index)` 统一处理 2–3 个选项，支持
  `food_cost` / `effects` / `roll`（概率分支）/ `battle` / `recruit` / `observe` / `rain_food`；
  旧式 `battle` + `choose_encounter("fight"/"talk"/"avoid")` 保留兼容。
- **探索改食物代价**：腐木探路深入 −2 食物得种子、浅探 −1 食物 +2 食物；掠食鸟影为占位 −1 食物（Q-123）。
- **事件池迁移**：旧 5 类已并入新 6 类，`pressure` 标记保留用于压力事件兜底。

### 4.8 招募 v2（2026-11-09）

- **池子**：24 = 共享 12 + 廪实专属 12；`tier` = 1 / 2 / 3，对应巢穴 **L1 / L2 / L3**。
  L1 可用 12 个、L2 累计 20 个、L3 累计 24 个。
- **阶级出现率**（`balance.recruit.tier_rates`，按巢穴等级取表）：
  L1 一阶 100%；L2 一阶 60% / 二阶 40%；L3 一阶 45% / 二阶 35% / 三阶 20%；
  每个候选独立掷点。
- ** affordability**：单个兵种食物成本 > 当前食物时不进入候选池（文档允许「不进候选或置灰」）。
- **升阶保底**：扩建到 L2 / L3 时把 `recruit_pity_tier` 设为 2 / 3；下一次招募先塞 1 个
  该阶级且付得起的单位，然后清 0。刷新不会重复触发保底（保底只作用于该次招募的第一次生成）。
- **其他**：3 候选、可刷新一次；同种候选允许重复（Q-106 未定，暂按允许处理）。
- **未做**：探索解锁（种子 → 兵种映射未定，Q-067）、专属虫种切换、虫珀刷新。
