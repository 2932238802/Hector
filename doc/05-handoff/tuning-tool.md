# 网页调参工具需求（交给开发 Agent 实现）

> 目标：**改数值 → 保存 → 游戏内 1 秒生效**，把调参循环从"改文件 + 重启游戏"压到"改一个输入框"。
> 本文只写**外部行为与验收标准**；技术选型、框架、UI 布局由实现层决定。

## 1. 使用场景

- 单人本地开发：浏览器打开网页，改数字，Godot 调试运行时立刻看到效果。
- 不联网、不部署、不需要账号。
- 工具与 Godot 可同时运行，互不阻塞。

## 2. 必须有的功能

### 2.1 数据读取与编辑

| 功能 | 要求 |
|---|---|
| 文件列表 | 列出 `data/` 下全部 JSON（units / enemies / events / balance / species / relics） |
| 表格视图 | 兵种、敌人、事件以表格编辑；`balance` / `species` 以表单编辑 |
| 逐字段编辑 | 数值用输入框，枚举用下拉框，文本用文本框 |
| 未保存提示 | 有改动未保存时明显提示，离开页面前拦截 |
| 保存 | 写回原 JSON，保留 `schema_version` 与未知字段（**不得丢弃实现层自加的字段**） |

### 2.2 校验（保存前强制）

- 按 `data-contract.md` §8 全部校验。
- 错误必须定位到**具体文件 + 条目 id + 字段名**，不允许只弹一句"保存失败"。
- 校验失败**拒绝写入**。
- 跨文件引用校验：事件引用的敌人 / 虫珀 / 种子必须存在。

### 2.3 预算预览（核心价值，不是装饰）

输入「我方阵容 + 敌方阵容」，输出：

- 我方每单位期望每轮输出 = `攻击 × 技能倍率 × 1.0`（连射等概率按期望展开）。
- 敌方同项。
- 预计清场轮数 = 敌方总 HP ÷ 我方每轮有效输出（简单估算即可，需在 UI 里注明"估算，不含前后排与护盾"）。
- 与 `balance.combat.target_rounds`（3–4 轮）对比给出 **偏快 / 合适 / 偏慢** 三档颜色。

> 估算公式以实现层为准，但**必须**使用数据文件里的数值，不得在代码里另存一份。

### 2.4 版本接口（给 Godot 轮询用）

- 提供只读接口返回**每个文件的修改时间或递增版本号**，供 Godot 判断"要不要重载"。
- 版本号必须在**保存成功后**才递增；校验失败不递增。

### 2.5 其他

- 只监听 `127.0.0.1`，不对外开放。
- 页面刷新后保持当前数据集（重新读文件即可）。
- 控制台/页面显示最近一次保存时间与操作结果。

## 3. 非目标（本期不做）

- 不做美术 / 场景预览。
- 不做事件组模拟器（只做数值预算）。
- 不做多人协作、账号、权限。
- 不直接连 Godot 进程（走文件 + 轮询即可）。
- 不提供"一键回滚"（版本管理交给 git）。

## 4. 接口建议（可调整，但必须满足 2.4）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/files` | 返回文件清单与版本号 |
| GET | `/api/file?name=units` | 返回单个文件内容 |
| PUT | `/api/file?name=units` | 校验通过后写入，返回新版本号 |
| GET | `/api/version` | 返回全部文件版本号（Godot 轮询这个） |

错误返回：HTTP 400 + `{ "errors": [ { "file": "...", "path": "units[3].hp", "message": "..." } ] }`。

## 5. 验收标准

- [ ] 改 `units.json` 里任一兵种的 `attack`，保存后 `/api/version` 递增。
- [ ] 把 `hp` 改成 `-1`，保存被拒绝，错误精确定位到 `units[i].hp`。
- [ ] 删除一个被事件引用的敌人，保存被拒绝并指出引用方。
- [ ] 网页保存后，Godot 调试运行中的实例在 **1 秒内**收到数据更新（非战斗字段即时生效）。
- [ ] 保存过程中 Godot 读到的是完整文件（不得出现半截 JSON 崩溃）。
- [ ] 工具只能在 127.0.0.1 访问。
- [ ] 预算预览对"锐士 + 弩手" vs "3 个掘沙虫"给出的轮数落在合理区间，并能标出偏快/偏慢。

## 6. 与热更的关系

工具只负责**写文件 + 暴露版本号**；游戏如何感知变化见 `hot-reload.md`。
两边**不得**通过私有的进程间通信耦合——文件是唯一接口。
