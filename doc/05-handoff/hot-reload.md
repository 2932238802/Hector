# Godot 热更需求（交给开发 Agent 实现）

> 目标：调参工具保存数据后，**正在运行的调试版游戏在 1 秒内拿到新数据**，不重启、不重新导出。
> 本文只规定**外部行为**；轮询 / 文件监听 / 信号实现由实现层决定。

## 1. 适用范围

- **只在编辑器内调试运行 / 开发构建**生效。
- 导出后的正式包**不得**依赖外部 `data/` 目录；正式包用打包进资源的数据（实现层决定方式）。
- 运行环境：Windows / WSL2 均可；数据目录以工程内 `data/` 为准。

## 2. 生效时机（2026-11-09 定）

| 字段类别 | 字段 | 生效时机 |
|---|---|---|
| 展示 / 经济 | `name` / `role` / `text` / `cost_food` / 事件文本与选项 / 奖励 / 权重 | **立即** |
| 战斗数值 | `hp` / `attack` / `ap` / `row` / `keywords` / `signature.params` | **下一场战斗生效** |

- **理由**：战斗中途改 HP 会让场上单位突然变血，产生无法复现的现象。
- 若改动发生在**战斗外**（地图 / 事件中），战斗数值也应立即用于下一场。
- 正在进行的战斗**保持开战时快照**，直到战斗结束。

## 3. 行为契约

| 要求 | 说明 |
|---|---|
| 检测周期 | ≤ 1 秒 |
| 数据来源 | `data/` 目录下的 JSON，按 `data-contract.md` |
| 无效数据 | **拒绝加载**，保留上一份有效数据，控制台输出错误；调试版可在界面显示一条警告 |
| 半截文件 | 不得崩溃；读到解析失败就当作无效数据 |
| 缺失文件 | 保留上次有效版本，记录错误；首次启动即缺失则使用工程内默认数据并报错 |
| 版本判断 | 用文件修改时间或工具提供的版本号均可，但必须能识别"内容变了"而非只看大小 |

## 4. 对外接口（行为级，命名由实现层定）

游戏内其他系统需要能：

1. 查询热更后是否已应用（例如战斗开始前取一次快照）。
2. 订阅"数据已更新"事件，用于刷新 UI 文本与数值显示。
3. 按 id 取兵种 / 敌人 / 事件 / 常数。
4. 查询当前数据版本号。

> 具体是信号、autoload、单例还是资源，由实现层选择，但**必须单一入口**，不得让各系统各自读文件。

## 5. 数据一致性

- 一次保存涉及多个文件时，游戏应**按文件粒度**更新，不要求跨文件原子性；但同一文件必须整体成功或整体失败。
- 更新后，已打开的面板要刷新；已部署单位的当前 HP **不变**，只影响新生成的单位。
- 战斗开始时的快照必须包含：双方单位数值、天气、事件效果——战斗中不再读数据。

## 6. 验收标准

- [ ] 调试运行中，改 `units.json` 里锐士的 `name`，1 秒内界面显示新名字。
- [ ] 改锐士 `hp`，当前战斗不受影响；下一场战斗按新 HP 生成。
- [ ] 保存一个语法错误 / 校验失败的 JSON，游戏不崩溃，继续用旧数据并报错。
- [ ] 连续快速保存 5 次，游戏最终状态与最后一次保存一致，无重复加载导致的异常。
- [ ] 战斗中保存数据，战斗结算正常，下一场使用新数值。
- [ ] 正式导出包不读取外部 `data/` 目录仍能正常运行。

## 7. 与调参工具的关系

- 唯一接口是 `data/` 文件（+ 可选版本号接口）。
- 不得通过私有 IPC、内存共享、调试端口耦合。
- 工具与本需求可以分别实现、分别验收。
